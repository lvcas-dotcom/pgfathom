# Recovery rate on the corpus

Generated by `make benchmark`. Do not edit by hand.

The procedure is the same for every schema: load it, read the declared foreign
keys, drop all of them, and ask the tool how many come back. The ground truth is
read by the harness's own query rather than through the catalog reader being
measured: a bug there would drop a key from the numerator and the denominator at
once, and the recall would look perfect for the wrong reason.

**No verdict is measured here.** The public corpus is DDL without a single row,
so nothing can be confirmed or broken. What these tables measure is whether the
right candidate was *raised*. The rule that no false positive may be confirmed
lives with the integration fixtures, where the answer was built alongside the
scenario and a wrong confirmation is recognisable as wrong.

**Naming detection is measured with its input removed.** It derives the local
reference affix by reading the foreign keys a schema already declares — and this
procedure drops every one of them first. So the `+ detection` row here describes
a schema that declares no integrity at all, which is the hardest case and a real
one, rather than the case where detection was measured at +78 points against
private schemas that still carried 470 declared keys. The two regimes are
different questions, and this corpus can only ask the first.

Tool `dev`.
